# P7 stackless board/root metadata prototype

2026-11-01. Added a read-only root-property pass after the full bounded structure/duplicate scan. [Assembly](../tools/entry-harness/handoff.S), [runner](../tools/test_entry_handoff.py), [retained evidence](evidence/p7-entry-root-tests.json). This is still isolated test code, not a production Pi entry path.

The pass seeks the root across leading NOPs, then scans its property region until the first child or root end. It requires explicit `#address-cells` and `#size-cells`, each exactly one big-endian u32 with value one or two. It validates the entire root `compatible` value as a nonempty NUL-terminated list of nonempty printable strings and requires an exact `raspberrypi,model-zero-2-w` entry. Prefix matches and a valid board followed by malformed list contents fail. No child property can establish root identity because the pass stops before children.

The earlier complete structure/duplicate pass establishes property bounds, name termination, ordering and uniqueness before this rescan. x26 is the root cursor, x27 current value size, x28 its start, x8 the required-field flags and x29/x30 the decoded address/size-cell counts. x1–x7/x9/x12 are string-comparison scratch. Required-field literals are read-only image data. Remaining registers retain the bounded DTB/structure/string extents and observed CPU state. No calls, stack or temporary RAM are introduced. This is a phase-specific allocation; future semantic passes must preserve or deliberately reload these values.

The root property region is a subset of the checked DTB, at most 2 MiB and 256 properties. Compatibility scanning advances within each value without backtracking; name comparison uses bounded, already-validated strings and fixed literals. It does not add an unbounded traversal. The previous global duplicate-rescan work cap remains enforced before this pass.

All 58 emulator scenarios pass. Thirteen new fixtures cover exact identity, one/two cell counts (including mixed widths), a board identifier later in a compatible list, wrong board, prefix-only match, missing terminator, empty value/entry, malformed trailing entry, missing board, zero/unsupported/missing cells. Every root fixture includes a leading NOP. Successful cases additionally check decoded counts in x29/x30. Existing markers, exact park PCs, vectors, instruction count and no-store/call/SP checks continue to pass.

This is not RAM safety: active memory nodes, tuple extraction, whole-kernel/DTB containment, tree reservations and D20 dynamic-request validation still require register-only passes. No stack write is authorized. Production CPU masks/full affinity, data-abort coverage, runtime write tracing, kernel wiring and physical Pi acceptance remain pending.
