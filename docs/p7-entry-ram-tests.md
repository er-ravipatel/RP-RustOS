# P7 narrow register-only RAM containment pass

2026-11-01. Added an optional test-only RAM semantic pass after checked header, reservation-map, structure, duplicate and root-property passes. [Assembly](../tools/entry-harness/handoff.S), [differential runner](../tools/test_entry_ram.py), [retained evidence](evidence/p7-entry-ram-tests.json).

This first pass deliberately supports one active root memory node with one `reg` tuple. It recognizes `memory`/`memory@...`, requires exact `device_type="memory"`, accepts missing/ok/okay status, skips disabled candidates and rejects unknown status. Candidate children are unsupported. It decodes one/two address and size cells using the checked root counts, rejects zero size, arithmetic wrap and out-of-board extents, and requires the entire [0x200000,0x400000) kernel budget and complete DTB to fit that bank. It rejects additional active memory candidates or additional tuples rather than merging them.

The pass reuses the fully bounded tree rather than treating raw memory as a tree. It keeps depth in x25, cursor in x26, candidate flag in x24, active-bank result in x8, device/status flags in x14/x15 and reg pointer/length in x16/x17. x29/x30 retain root cell counts; x19/x20 retain the complete DTB extent. x1–x7/x9/x12 and current value registers are scratch. It performs no calls, recursion, stores or stack operations. Name/property rescans advance through already-validated extents; this phase does not introduce arbitrary rescanning or an allocator.

All 15 RAM scenarios pass. The runner supplies identical synthetic DTB bytes to the assembled emulator pass and the host Rust reference, recording both results and hashes. Coverage includes one/two cell widths, ok/okay status, zero size, partial kernel/DTB containment, disabled/unknown status, overlapping/multiple tuples, split kernel, board ceiling, u64 wrap and a bank starting after the kernel base. Fourteen cases agree on acceptance/rejection; the fifteenth deliberately demonstrates the narrower assembly subset: a valid multiple-bank map accepted by Rust is conservatively rejected by the prototype. No false acceptance is justified by that difference.

Crucial remaining limit: the optional RAM pass does not inspect reserved-memory tree nodes, D20 dynamic request shape or every malformed memory-node identity outside its candidate set. Header reservations are checked by the prior pass, but that is not the complete reservation set. A valid RAM containment result therefore does **not** authorize a private stack or BSS write. Full production CPU masks, complete affinity, data-abort coverage, write tracing, kernel wiring and physical Pi acceptance also remain open. The test markers are host-harness observations, not startup success output.

The existing 58 entry/header/map/structure/root cases were rerun after this change and all passed; [regression evidence](evidence/p7-entry-ram-regression.json) is retained separately from the 15 RAM comparisons.

Next: bounded reserved-memory semantic checks, further malformed-node fixtures and reconciliation of the conservative bank limit with firmware handoff evidence. Only then consider a first-write boundary. No firmware asset, accepted M1 kernel or physical card was changed.
