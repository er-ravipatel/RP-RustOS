# Project work records

For every code change, add or update a visible entry in `docs/tracking.json` under `work_updates`. Include a plain-language summary, validation results, remaining work or limitations, and documentation/evidence references. Record the commit hash when available; a null commit links to project history for the change committed with the record. Keep the dashboard current throughout implementation, including incomplete or failed work, without claiming unperformed validation.

Validate the tracking register and relevant dashboard tests before committing. Continue to commit verified work separately with a descriptive subject and body, and push to the configured RustOS GitHub repository as authorized by the user. Never publish downloaded archives or generated build outputs by removing their ignore rules.
